---
name: API bundle in workspace odvisnosti
description: Pravilo za esbuild external vzorce in produkcijsko objavo workspace API-ja.
---

Zunanje odvisnosti, ki jih uporablja API bundle, ne smejo ostati odvisne od korenskega `node_modules`, ker ga Publish zaradi velikosti slike namenoma izloči. Čiste JS pakete je dovoljeno vključiti v bundle; native oziroma datotečno občutljive pakete je treba zgraditi kot omejeno produkcijsko drevo iz workspace lockfile stanja, ga obrezati po dejanski dosegljivosti in nato shraniti kot en neprozoren arhiv. Ohlapno package drevo ne sme ostati v `dist`, tudi če je fizično hoisted in preimenovano, ker ga Publishovo čiščenje še vedno lahko odstrani. Produkcijski bootstrap naj takoj odpre zahtevani port v stanju »starting« in mora na konfigurirani startup-health poti vrniti HTTP 200; druge poti lahko do pripravljenosti ostanejo 503. Nato preveri kontrolno vsoto arhiva, ga atomsko razširi v vsebinsko verzionirano mapo pod `/tmp` in šele nato preda port aplikaciji. Iz bundlea pakete nalagaj neposredno prek namenskih shimov; ne ustvarjaj nadomestnega `node_modules` symlinka.

**Why:** Lokalni workspace je prikril manjkajoče runtime pakete. Startup symlink in pozneje tudi preimenovano fizično hoisted drevo sta lokalno delovala, Publishovo čiščenje pa je iz slike odstranilo dosegljiv `@google-cloud/storage`; API zato ni odprl porta in je vračal health-check 500. En arhiv ne izgleda kot paketni cache, hkrati pa ohrani native module in datoteke, ki jih knjižnice nalagajo relativno. Hladna Autoscale instanca lahko za pripravo arhiva porabi več kot omejitev zaznavanja porta, zato mora biti port viden že med pripravo. Replitova startup proba zahteva HTTP 200 na konfigurirani poti; odprt port z začasnim 503 se še vedno obravnava kot neuspešen zagon.

**How to apply:** Po spremembi esbuild `external` vzorcev ali runtime pakiranja preveri, da `dist` vsebuje arhiv in nobenega `node_modules`, `.pnpm` ali ohlapnega runtime package drevesa. Nato kopiraj samo `dist` v izolirano mapo, izbriši `/tmp` cache, zaženi produkcijski entrypoint in preveri takojšnji health 200 z vsebino »starting«, sočasni 503 na poslovni poti, poznejši pravi health 200, strogo validacijo porta, sočasno ekstrakcijo ter dejanski klic native modula; ne zanašaj se samo na uspešen build.

Združljivostni popravki za pakete, ki so že vključeni v bundle, ne smejo uporabljati runtime `require.resolve` za isti paket: po Publish čiščenju ta lookup odpove, čeprav je dejanska koda paketa že v bundleu. Odvisni parser ali pomožni modul naj bo neposredna produkcijska odvisnost in statični uvoz. Začasna pnpm deploy drevesa vedno gradi zunaj `artifacts/`, sicer jih lahko workspace med daljšim buildom napačno registrira kot samostojen artefakt.
